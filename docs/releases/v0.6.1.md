# v0.6.1

## 优化改进

- 后台统计改为保留每日收信计数，过期邮件被清理后，管理员仍能在趋势图和增长统计里看到历史收信量。
- SQLite 默认数据库文件名统一为 `hlool-mail.db`；从旧版本升级且仍使用 `gptmail.db` 的实例会自动继续读取旧库，避免升级后误进入空数据库。
- DNS/MX 检测会解析并校验自定义解析器和权威 DNS 地址，阻止 localhost、云元数据地址、内网地址和保留地址，减少 DNS 检测被误用的风险。
- Webhook 表单在前端提前拦截非公网 HTTPS、localhost、内网和带账号密码的 URL，提交前就能看到更清楚的提示。
- GitHub Actions 发布链路增强：CI 会在版本 tag 上运行，Docker 和二进制发布工作流会校验 `vX.Y.Z` tag，并统一使用云端 npm registry 配置完成构建。

## 修复问题

- 修复后台统计在邮件清理后按实时消息表计算，导致历史收信趋势和增长数字偏低的问题。
- 修复分享访问密钥出现在 URL query 中的问题；新生成的分享链接会把 key 放到 fragment，减少代理、日志和 Referer 泄露风险。
- 修复邮件 HTML 预览会向 `/api/...` 链接自动追加 API Key 的问题，避免邮件正文链接暴露访问凭据。
- 修复 5xx 响应可能把内部错误细节返回给前端的问题；现在对外只返回通用错误文案，详细错误保留在服务端日志。
- 修复 Linux.Do OAuth 在用户信息接口异常时回退解析未验证 `id_token` 的问题，避免登录资料被不可信来源补全。
- 修复 OAuth 回调地址提示仍显示旧路径的问题，现在控制台提示会使用实际的 `/api/oauth/{provider}/callback` 地址。
- 修复旧版 `X-Admin-Token` 默认仍可用于管理接口的问题；现在必须显式设置 `ALLOW_LEGACY_ADMIN_TOKEN=true` 才会启用。

## 部署说明

- 本次为补丁版本，目标版本为 `0.6.1`，发布 tag 为 `v0.6.1`。
- 使用 SQLite 的旧实例无需立即改名数据库文件；如果要手动迁移，请停机后同时重命名 `gptmail.db`、`gptmail.db-wal`、`gptmail.db-shm`。
- 仍依赖 `X-Admin-Token` 的旧脚本需要先改用管理员登录会话；短期兼容可临时设置 `ALLOW_LEGACY_ADMIN_TOKEN=true`。
- 本次按云端校验和云端打包处理；推送 `main` 与 `v0.6.1` tag 后，由 GitHub Actions 完成 CI、Docker 镜像发布和 Release 二进制打包。
