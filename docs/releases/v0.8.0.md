# v0.8.0

## 新增功能

- 新增可选 Prometheus 指标出口，开启 `METRICS_ENABLED=true` 后可通过 `/metrics` 观察 HTTP、SMTP、数据库和 webhook 处理状态。
- 新增请求 ID 贯穿能力，接口响应和结构化日志会带上同一条请求链路，便于排查线上问题。
- 新增数据库迁移基线能力，为后续 PostgreSQL 结构升级提供可追踪的迁移记录。
- 新增 OpenAPI 快照、前端类型生成和路由一致性校验，减少前后端接口漂移。

## 优化改进

- 强化 PostgreSQL 连接池配置，支持设置最大打开连接数和最大空闲连接数，并在关键配置缺失或不安全时尽早提示。
- 优化 Docker 部署体验，容器加入健康检查，Compose 会等待数据库健康后再启动应用。
- 优化 SMTP 入口防护，增加连接并发控制和限速能力，降低异常流量对服务稳定性的影响。
- 统一 HTTP 与 SMTP 的限流实现，避免高基数访问来源长期堆积内存。
- 统一服务日志为结构化日志，并加入 GORM 慢查询日志，方便在生产环境检索和定位瓶颈。
- 强化 CI 流水线，远端会执行 Go 覆盖率测试、关键包 race 测试、前端接口检查、类型检查、构建、Docker Compose 校验、镜像构建和 Trivy 扫描。

## 修复问题

- 修复登出清理 Cookie 时 SameSite 属性不一致导致部分浏览器可能残留会话的问题。
- 修复 OpenAPI 文档可能与实际注册路由不一致的问题。
- 修复 SMTP 连接缺少全局约束时可能被异常并发拖慢的问题。
- 补充复杂 MIME 边界解析覆盖，降低特殊邮件格式解析回归风险。

## 部署说明

- 本次目标版本为 `0.8.0`，发布 tag 为 `v0.8.0`。
- 按本次发布要求跳过本地发布前验证；推送 `main` 与 `v0.8.0` tag 后，由 GitHub Actions 完成 CI、Docker 镜像发布和 Release 二进制打包验证。
- 指标出口默认关闭，需要观测指标时设置 `METRICS_ENABLED=true`。
- 使用内置 PostgreSQL 的 Compose 部署会自动等待数据库健康；使用外部数据库时，建议通过 `docker compose up -d --no-deps app` 单独升级应用容器。
- 本版本会创建数据库迁移记录表，当前基线迁移不改变业务表结构，现有部署可从 `v0.7.2` 直接升级。
