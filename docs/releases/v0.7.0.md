# v0.7.0

## 新增功能

- 新增泛子域邮箱生成能力。用户可以选择父域并生成 `user@label.example.com` 形式的邮箱，子域标签可手动填写，也可以留空自动生成。
- 可用域名列表现在会标明普通邮箱和泛子域邮箱能力，客户端可以清楚区分哪些域名适合生成 `user@example.com`，哪些域名适合生成 `user@label.example.com`。
- 收件箱发件人头像新增品牌图标解析能力，会优先展示发件域名的 BIMI、站点图标或 favicon，让邮件列表更容易识别来源。

## 优化改进

- 域名验证状态改为按能力判断：只配置通配 MX 的域名也可以被识别为可用于泛子域邮箱，不再必须同时完成根域 MX。
- Web Console 的邮箱生成入口新增“普通邮箱 / 泛子域邮箱”切换，并会按当前模式过滤可选域名。
- 域名添加和 DNS 提示文案更新为父域管理模型，减少把 `*.example.com` 当作真实邮箱后缀的误解。
- YYDS 兼容接口同步支持泛子域邮箱能力，并在响应中返回父域、子域和通配模式信息。
- API 文档、OpenAPI 描述和 Codex skill 参考已同步更新泛子域邮箱用法。

## 修复问题

- 修复已单独登记的子域可能被父域通配规则错误接管的问题，保护具体子域的域名归属和邮件访问权限。
- 修复通配域邮箱中包含 `*` 的完整地址可能进入收信流程的问题，现在这类地址会被判定为无效收件人。
- 修复同一个邮箱地址在不同解析域名之间复用时可能归属错误的问题，避免父域通配邮箱影响具体子域收件人。
- 修复域名健康检测、自动重试和首次验证时间对通配 MX 能力判断不一致的问题。

## 部署说明

- 本次为功能版本，目标版本为 `0.7.0`，发布 tag 为 `v0.7.0`。
- 本次按用户要求跳过本地验证，推送 `main` 与 `v0.7.0` tag 后，由 GitHub Actions 完成 CI、Docker 镜像发布和 Release 二进制打包。
- 使用泛子域邮箱时，请添加父域 `example.com`，并在 DNS 中配置 `*.example.com` 的 MX 记录；`*.example.com` 是 DNS 通配模式，不是邮箱后缀。
